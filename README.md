## 레포 구조

```
platform/g431-esc1/   보드 공용 계층 — 실험마다 동일한 것은 전부 여기 한 벌만
├── g431-esc1.ioc         CubeMX 프로젝트 (보드 단위 하나)
├── Core/, Drivers/       CubeMX 생성물 (HAL·CMSIS 포함)
├── bsp/                  손으로 쓴 보드 공용 코드 (핀 래퍼 등)
├── platform.cmake        프로젝트가 부르는 add_lab_firmware()
└── template/             새 실험 시작용 복사본

projects/pN-이름/      실험 하나 = 폴더 하나
├── src/                  실험 코드 + 짧은 CMakeLists (platform 참조)
├── data/                 측정 데이터 (선별해서 커밋)
└── docs/                 회로도, 배선 사진 등

log/                  실험 하나 = 글 하나
notes/                이론 학습 노트
```

보드는 항상 B-G431B-ESC1 하나다. 그래서 HAL·CMSIS·startup·링커스크립트는
실험마다 복사하지 않고 `platform/g431-esc1` 한 벌을 공유한다.
새 실험은 `platform/g431-esc1/template/` 를 복사해서 시작한다 —
CubeMX를 새로 돌리지 않는다.

## 기록 규칙

1. **단위**: 실험(또는 공부 주제) 하나 = 글 하나. 몰아서 쓰지 않는다.
2. **위치와 이름**: `log/YYYY-MM-DD-제목.md` (예: `log/2026-08-02-closed-loop-position.md`).
   이미지·그래프는 `log/img/`에 넣고 글에서 상대경로로 링크.
3. **형식**: [log/_template.md](log/_template.md) 복사해서 시작.
   "뭘 하려고 했나 → 뭘 했나 → 막힌 것과 해결 → 배운 것" 순서. 막힌 과정이 본편.
4. **타임라인 갱신**: 글을 올리면 이 README 타임라인에 한 줄 추가 (최신이 위).
5. **코드·데이터**: `projects/` 아래 해당 프로젝트 폴더에 커밋하고 글에서 링크.
   데이터는 선별해서 커밋 (원시 로그 전체 X, 그래프 재현에 필요한 것만).
   보드 공용 코드는 `projects/` 가 아니라 `platform/g431-esc1/bsp/` 로 간다.
6. **실패도 기록**: 안 된 튜닝, 태워먹은 부품, 잘못 짚은 원인 전부.
   포트폴리오는 성공담이 아니라 문제 해결 서사다.
7. **커밋 메시지**: `log: 2026-08-02 클로즈드루프 위치 제어` / `p1: 엔코더 캘리브레이션 코드` 식으로
   접두어(log/p1/p2/…/notes/platform)를 붙인다.
8. **"되게 했다"에서 멈추지 않는다**: 왜 되는지 설명이 붙어야 글 완성.

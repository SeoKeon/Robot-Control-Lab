# 2026-10-10 첫 클로즈드루프 — 오프셋 캘리브레이션과 엔코더 기반 정류

## 뭘 하려고 했나

같은 날 오전에 엔코더 각도를 믿을 수 있게 됐다(→ [지그·엔코더 검증](2026-10-10-jig-and-encoder-validation.md)).
이제 각도를 **읽기만** 하지 않고 **써서** 모터를 돌린다.

오픈루프는 로터가 어디 있든 회전 자기장을 정해진 속도로 끌고 다녔다. 이번엔
매 순간 실제 로터 각도를 읽고, 벡터를 항상 **로터보다 전기각 90도 앞**에 세운다.
토크가 최대가 되는 각도에 고정하는 것이다. 전류 센서는 아직 없으니 전압 크기
`m` 으로 힘을 정한다 — **전압 모드 FOC**.

그러려면 먼저 "엔코더 0도가 전기각 몇 도인가"(오프셋)를 알아야 한다.

## 뭘 했나

### 1. 펌웨어를 명령 방식으로

처음엔 캘리브레이션 → 주행 → 브레이크 테스트를 한 번에 이어 돌리게 했는데,
"언제 손을 대야 할지 헷갈린다"는 피드백으로 단계를 나눴다. 시리얼 명령
`c`(캘리브레이션) / `r`(손 안 대는 주행) / `b`(브레이크 테스트 20초) / `q`(정지).
오프셋은 RAM 에 남아서 한 번 재면 여러 번 돌릴 수 있다.

### 2. 오프셋 캘리브레이션

전기각을 30도씩 앞으로 한 바퀴, 뒤로 한 바퀴 돌리며 매 위치(24점)에서

```
offset = θe(명령) − 부호 × 7 × θm(엔코더)
```

를 구해 원형 평균했다. 2회 반복.

| | 1회차 | 2회차 |
|---|---|---|
| 1바퀴 기계 이동 (기대 51.4도) | 51.4도 | 51.6도 |
| **오프셋** | **−72.5도(전기)** | **−72.5도(전기)** |
| 24점 흩어짐 최대 | 7.9도 | 7.8도 |
| 앞으로 평균 − 뒤로 평균 | −0.1도 | −0.1도 |

두 번의 차이 **0.0도**. 극쌍수 7 도 1바퀴 이동량(51.4도)으로 다시 확인됐다.

### 3. 손 안 대는 주행 (`r`)

| 단계 | m | 정상 속도 (1.5초 이후 평균) | 흔들림 (표준편차) |
|---|---|---|---|
| 저속 정방향 | 0.25 | **211 rpm** | 7 |
| 정방향 | 0.30 | **255 rpm** | 6 |
| 역방향 | 0.30 | **−251 rpm** | 7 |

루프 주파수 약 2 kHz (I2C 각도 읽기가 병목). 관찰: **소리 없이 부드러움**.
전원 전류: 캘리브레이션(정지 벡터) 약 0.2A, 회전 중 **약 0.13A**.

### 4. 브레이크 테스트 (`b`)

정방향 m=0.30 으로 20초 동안 돌리면서 표시판을 손가락으로 눌렀다.

```
 0 ~ 6초    256 rpm            손 안 댐 (기준)
 6 ~ 7.5초  → 0                누름, 멈출 때까지 잡음
 8 ~ 8.5초  224                뗌 → 바로 재가속
 9초        58                 다시 누름
10 ~ 11.5초 256                뗌 → 원래 속도
12 ~ 15.5초 0                  약 3.5초 완전히 잡음
16 ~ 17.5초 199 → 256          뗌 → 0.5초 안에 복귀
18 ~ 20초   0                  잡은 채 종료
```

관찰: **밀어내는 느낌, 진동 없음.** 전원 전류 **0.13A → 0.16A** (누를 때).

[브레이크 테스트](../projects/p1-foc-bringup/data/2026-10-10-commutation-brake.txt)

## 막힌 것과 해결 과정

### 사람이 끼는 실험은 단계를 쪼갠다

시간에 맞춰 손을 대야 하는 실험을 한 번에 이어 돌리면, 사람은 지금 어느 단계인지
알 수 없다(시리얼 출력은 내가 보고 있으니까). 명령 방식으로 바꿔서
"지금부터 20초, 아무 때나"로 만들었다. **측정하는 쪽이 아니라 조작하는 쪽 기준으로
실험을 설계할 것.**

### 출력 매크로가 음수 부호를 잃었다

nano printf 에 `%f` 가 없어서 쓰던 `정수.소수` 매크로가 −1 ~ 0 사이 값(예: −0.3)을
`0.3` 으로 찍었다. 오프셋이나 앞뒤 차처럼 0 근처 음수가 나올 값에서 치명적이라
`snprintf` 기반 헬퍼로 바꿨다. 첫 실행 전에 잡았다.

## 배운 것 / 다음 할 것

### 숫자가 서로를 검증한다 (이번에도)

- **정방향 255 rpm, 역방향 −251 rpm (차이 1.6%)** — 오프셋이 맞다는 가장 강한 증거.
  오프셋이 틀렸다면 한 방향은 90도보다 더 앞서고 반대 방향은 덜 앞서서 두 속도가
  눈에 띄게 달라진다. 캘리브레이션 숫자와 독립적인 검증이다
- **속도 ∝ 전압**: 211 ÷ 0.25 = 845, 255 ÷ 0.30 = 850. 무부하에서 모터는 역기전력이
  인가 전압과 같아질 때까지 빨라진다 → 전압 모드에서 m 이 곧 속도 지령처럼 동작한다
- **돌 때 전류가 오히려 준다** (정지 벡터 0.2A → 회전 0.13A). 역기전력이 전압을
  상쇄해서 마찰을 이길 만큼만 흐른다. 오픈루프는 늘 최악을 가정해 전류를 밀어넣는다
- **누르면 전류가 는다** (0.13 → 0.16A). 느려진 만큼 역기전력이 줄고, 남은 전압이
  전류 = 토크가 된다. "밀어내는 느낌"은 제어가 아니라 이 물리가 만든 것

### 오픈루프와의 결정적 차이 — 탈조가 없다

세 번 멈춰 세웠다가 놓았는데 매번 0.5초 안에 원래 속도로 돌아왔다. 오픈루프는
자기장이 로터를 기다려주지 않아서, 한 번 멈추면 어긋난(탈조) 채로 떨기만 한다.
엔코더 기반 정류는 **항상 실제 로터 위치에서 90도 앞을 당기므로** 멈춘 자리에서
다시 출발한다.

### 전압 모드의 한계 — 다음 단계가 왜 전류 루프인가

잡고 있는 동안 역기전력은 0 이고, 전류는 `전압 ÷ 저항` 으로 최대가 된다. m=0.30 은
작아서 괜찮았지만, 토크를 키우려고 m 을 올린 상태에서 막히면 **전류를 막을 장치가
없다.** 전류를 직접 재고 제어하면(전류 루프) 막혀도 정한 전류 이상 흐르지 않는다.
그게 "전압 모드 FOC" 와 진짜 FOC 의 차이다.

또 하나: 루프가 2 kHz 라 각도가 최대 0.5 ms 늦다. 255 rpm 에서 전기각 약 5도라
지금은 무시할 만하지만, 빨라질수록 실제 앞섬이 90도보다 작아진다.

# 2026-08-29 AS5600 엔코더 브링업 — I2C 뚫기, 자석, 원인 가르기

## 뭘 하려고 했나

로터 실제 각도를 읽는 것. 오픈루프(08-27)는 로터가 어디 있는지 모른 채 벡터를
밀어붙이는 방식이라, 각도를 알아야 "명령각 vs 실제각" 비교가 되고 그 다음이
FOC 다. 모터에 딸려온 AS5600 보드(I2C)를 붙이기로 했다.

## 뭘 했나

### 배선 확정 (전부 문서·DB 로 확인 후 납땜)

| 신호 | 연결 | 근거 |
|---|---|---|
| SDA | J8 의 B+/H2 → **PB7** | CubeMX 칩 DB AF 목록 (`I2C1_SDA`) |
| SCL | J8 의 Z+/H3 → **PB8** | 〃 (`I2C1_SCL`) — 처음 추정 PB6/PB7 은 틀렸었다 |
| VCC | **J4 패드 3번 (3.3V)** | 엔코더 보드가 3.3V 전용인데 J8 은 5V 만 나옴. UM2516 Table 6 + 회로도 교차 확인 |
| GND | J8 GND | |
| DIR | GND | 방향 미정의 방지 (떠 있으면 각도 증가 방향이 랜덤) |

I2C 풀업은 따로 안 달았다 — J8 홀입력 회로에 +3.3V 10K 가 이미 있다.

### 순서대로 검증

1. **I2C 스캔**: `0x36` 응답, 이후 수백 회 읽기 에러 0건 → 배선·전원·풀업 전부 OK
2. **자석 상태**: `STATUS=0x13` → **ML=1 (자석 약함)**. raw 는 0 과 ~349도를 오락가락
3. **자석이 아예 없었다** — 사진으로 축 끝 확인. 여분 AS5600 보드 포장에서
   동봉 자석(소형 원판)을 발견해 축 끝에 테이프 고정
4. **각도 추종 확인**: 정지 시 raw ±2 카운트(±0.18도)로 고정, 손으로 돌리면
   4095→0 랩어라운드까지 부드럽게 추종. 단 **AGC=128 (최대) 고정** — 신호가
   판정 문턱 바로 아래. 간격을 더 못 줄이는 상태라 일단 진행
5. **통합 실험**: 오픈루프 연속 회전(정방향 2바퀴 + 역방향 1바퀴) + 엔코더
   동시 로깅. 엔코더 언랩, 부호 자동판정, 100ms 마다 cmd/enc/err 출력

## 막힌 것과 해결 과정

### CubeMX — 핀에 신호를 지정해도 주변장치는 안 켜진다

칩 그림에서 PB7/PB8 을 클릭해 I2C1 신호를 지정했는데, 생성해 보니
`MX_I2C1_Init()` 도 `hi2c1` 도 없었다. `.ioc` 를 보면 핀 신호만 있고
`Mcu.IP` 목록에 I2C1 이 없다. **핀 지정과 주변장치 활성화는 별개 단계다** —
왼쪽 Connectivity 에서 Mode 를 켜야 초기화 코드가 생긴다.
(USART2 때는 Mode 먼저 → 핀 이동 순서라 몰랐던 것)

### PB8 은 BOOT0 겸용 — 옵션 바이트가 미리 막아두고 있었다

PB8(SCL)은 `PB8-BOOT0` 이다. I2C 풀업 때문에 SCL 은 리셋 때 High 라서,
핀이 부트 모드를 결정하는 상태였다면 **엔코더를 꽂는 순간부터 매 리셋마다
부트로더로 빠지는 보드**가 됐을 것이다. 실측(`STM32_Programmer_CLI -ob displ`):

```
nSWBOOT0 = 0  (BOOT0 를 핀이 아니라 옵션 비트에서 읽음)
nBOOT0   = 1  (항상 메인 플래시 부팅)
```

ST 가 홀센서(풀업 라인)를 하필 이 핀에 배선하면서 옵션 바이트로 무해화해둔 것.
칩 교체나 mass erase 후엔 되돌아갈 수 있다 — "엔코더 꽂으면 부팅 안 됨" 증상이
나오면 여기부터 볼 것.

### AGC=128 로 자석 부재를 진단

STATUS 의 ML 비트만으로는 "약함"까지만 안다. **AGC(0x1A)** 를 같이 읽으면
정량이 된다: 자동 게인이 최대치(3.3V 모드 128)에 붙어 있으면 "증폭을 끝까지
올려도 부족" = 사실상 자석이 없거나 아주 멀다는 뜻. 위치를 바꿔도 60초 내내
128 이었다 → 간격 조정 문제가 아니라 자석 부재로 판단했고, 맞았다.
**AGC 는 거리 게이지다** — 지그 조립 때 서포트 높이를 바꿔가며 60~90 을 맞추면 된다.

### 드리프트가 재현되지 않는다 — 원인이 둘로 갈린다

통합 실험을 두 번 돌렸다. 같은 명령인데:

| | 부호판정 구간 (기대 51.4도) | 최종 누적 오차 (기대 ~0) |
|---|---|---|
| 1차 | 90.9도 | -44.0도 |
| 2차 | 64.0도 | -21.6도 |

**재현되지 않는 오차 = 전기·스케일 문제가 아니다.** 순수 부하각은 최대
90/7 = 12.9도여야 하는데 관측이 40~50도라 다른 원인이 지배적이다. 후보 둘:

1. **기계 미끄러짐** — 자석은 테이프 고정이라 가감속 충격에 조금씩 밀릴 수 있다
2. **자기장 간섭** — 신호가 한계선(AGC=128)이라, 로터 링 자석 누설과 PWM
   전류가 만드는 스테이터 자기장이 상대적으로 크게 보인다

**판별 실험을 설계해뒀다: 전원 없이 손으로 정확히 2바퀴.** PWM 이 없으면
간섭원이 사라지므로 — 720도가 정확히 나오면 간섭(→ 간격을 좁혀 신호를 키워야
해결), 손으로 돌려도 오차가 쌓이면 미끄러짐(→ 접착). 현재 `foc_bringup` 에
이 펌웨어가 들어 있고, **엔코더를 제대로 고정한 뒤 첫 실행 대상**이다.

### 그래도 확인된 것

- PWM 구동 + I2C 읽기 + 시리얼 로깅 **동시 동작** (연속 회전 3바퀴 완주)
- 역방향 구간에서 err 부호 반전 — 로터가 늦게 따라오는 **추종 지연이 데이터에
  실제로 보인다.** 부하각 δ 의 그림자다. 지금은 드리프트에 묻혀 있을 뿐

## 배운 것 / 다음 할 것

- **재현성이 최고의 진단 도구다.** 같은 입력을 두 번 — 오차가 같으면 계통
  (스케일·설정), 다르면 랜덤(기계·노이즈). 공짜로 원인 공간이 반으로 준다
- **변인 하나를 제거하는 실험을 설계한다.** 전원 OFF 손돌리기 = 간섭원 제거.
  08-05 층별 진단 틀의 연장: 층을 못 가르면 층 하나를 꺼보면 된다
- **센서 진단 레지스터를 먼저 읽는다.** MD/ML/MH/AGC 를 몰랐으면 "값이 이상하다"
  에서 며칠 헤맸을 것. 데이터시트의 status/diagnostic 장이 디버깅의 절반이다
- 하드웨어 준비물: 지그(M2 서포트 + 플레이트), 자석 접착(또는 더 강한 고정),
  간격 0.5~1mm 로 AGC 60~90 확보

### 다음 (엔코더 고정 후)

1. 무전원 손돌리기 판별 테스트 (펌웨어 준비됨) — 720도 정확도 확인
2. 원인에 따라: 간섭이면 간격 축소, 미끄러짐이면 접착
3. 통합 실험 재실행 — 성공 기준: 부호판정 51.4±2도, 최종 오차 ±13도, 2회 재현
4. 통과하면 → 엔코더 기반 정류 (각도를 알고 벡터를 +90도에 세우기 = FOC 의 절반)

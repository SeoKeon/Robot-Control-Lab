# 2026-10-10 지그 장착과 엔코더 검증 — 드리프트 -44도에서 ±1도로

## 뭘 하려고 했나

08-29 에 엔코더를 붙이고 오픈루프 회전과 함께 로깅해 봤는데, 명령각과 실제각의
오차가 두 번 돌릴 때마다 달랐다(1차 −44도, 2차 −21.6도). 원인 후보는 둘이었다.

1. **기계 미끄러짐** — 자석을 테이프로 붙여 두었다
2. **PWM 자기장 간섭** — 신호가 한계선(AGC=128)이라 모터 자기장에 약하다

3D 프린팅으로 테스트 거치대(→ [`hardware/foc-test-stand/`](../hardware/foc-test-stand/))를
만들어 모터·자석·센서를 제대로 고정한 뒤, 이 둘을 가르고 엔코더를 검증하는 것.

## 뭘 했나

### 1. 지그 조립 후 I2C 가 죽어 있었다

판별 펌웨어를 올리자 출력이 전부 0, AGC 까지 0. 부팅 스캔 결과 `I2C1 scan: (0개)`.
조립하면서 엔코더 선 하나가 빠져 있었다. 원인을 찾으려고 **I2C 버스 진단 루틴**을
만들었다 (하드웨어 I2C 를 잠시 끄고 핀을 직접 본다):

| 단계 | 하는 일 | 이번 결과 |
|---|---|---|
| BUSY 플래그 | 누가 SDA 를 잡고 있는지 | 0 |
| 대기 레벨 | SDA/SCL 이 High 인지 (Low 면 단락 또는 칩 전원 없음) | 1 / 1 |
| 내부 풀다운 | 그래도 High 면 보드 10K 풀업 정상 | 1 / 1 |
| 버스 복구 | SCL 9발 + STOP — 걸린 슬레이브 풀기 | |
| 비트뱅 스캔 ×2 | 정상 배선 / SDA·SCL 뒤바뀐 배선 양쪽으로 | 0 / 0 |

→ MCU 쪽은 정상, AS5600 까지 가는 경로 문제로 좁혀졌고, 빠진 선을 찾아 끼우자
`0x36` 이 돌아왔다. 이 진단은 이제 부팅할 때마다 돌고 판정 문구를 찍는다.

### 2. 무전원 손돌리기 — 센서와 각도 계산 검증

PWM 없이 손으로 대략 2바퀴. 0점 표시는 못 했지만 엔코더가 **절대각**이라 검산이 된다:

```
시작 raw 2587 → 끝 raw 2782   = +195 카운트 = +17.1도
누적 각도 737.1도             = 720 + 17.1   ← 소수점까지 일치
```

바퀴를 하나라도 놓치거나 더 셌다면 360도 단위로 어긋났을 것이다.
→ **PWM 이 없을 때 센서와 언랩은 깨끗하다.** 이때 AGC 는 아직 128 이었다.

### 3. 스페이서로 간격 줄이기

| | MD | AGC (3.3V 모드 0~128, 작을수록 자기장 강함) |
|---|---|---|
| 테이프 고정 (08-29) | 0 | 128 |
| 지그, 스페이서 없음 | **1** | 128 |
| 지그, **스페이서 1.0 mm** | 1 | **21** |

1 mm 한 장으로 128 → 21. PWM 간섭이 의심 대상이었으니 신호는 강한 쪽이 유리해서
정중앙(~60) 대신 이걸 택했다.

### 4. 통합 실험 재실행 — 오픈루프 연속 회전 + 엔코더 로깅

08-29 와 같은 시퀀스(부호 판정 전기 1바퀴 → 정방향 기계 1바퀴 ×2 속도 → 역방향 1바퀴).
바꾼 것 두 가지: 시리얼 `s` 를 받아야 통전하게(12V 연결 전에 부팅돼도 안전),
회전 로그 매 줄에 AGC 를 붙였다(간섭이 있으면 회전 중 출렁일 것).

| | 1차 | 2차 | 기준 |
|---|---|---|---|
| 부호 판정 (기대 51.4도) | 50.2도 | 50.3도 | ±2도 |
| 최종 누적 오차 | −1.1도 | +0.7도 | ±13도 |
| 회전 중 AGC | 24 고정 | 24 고정 | 정지 기준 23~24 |

구간별 오차 (명령 − 실측, 기계각):

| 구간 | 1차 평균 (범위) | 2차 평균 (범위) |
|---|---|---|

| 속도 1 — 기계 57 deg/s | 1.2 (0.0 ~ 2.3) | 1.1 (0.1 ~ 2.3) |

## 막힌 것과 해결 과정

### "아무것도 안 했는데 검증이 어떻게 됐나"

진단 루틴은 보드가 혼자 한다. I2C 장치는 전원과 선만 살아 있으면 축 각도와 무관하게
자기 주소에 대답한다. 그래서 "전 주소에 물어보고 대답이 없다"는 것만으로 배선 문제가
확정된다. 사람 손이 필요한 건 손돌리기(720도) 단계뿐이었다.

### 가설을 실제 행동이 아니라 계획에서 세웠다

인수인계 문서의 "헤더를 칩 반대편으로 다시 납땜하기로 함" 을 이미 한 일로 보고,
뒷면에서 보면 핀 순서가 좌우 반전된다 → VCC/GND 가 바뀌었을 것이라는 가설을 1순위로
세웠다. 실제로는 납땜을 다시 하지 않았고 커넥터만 뺐다 꽂은 상태였다.
**문서에 적힌 "하기로 함"과 "했음"은 다르다** — 가설의 전제는 직접 확인할 것.

## 배운 것 / 다음 할 것

### 숫자가 서로를 검증한다

- **부호 판정이 50.2도인 이유**: 기대값 51.4도는 로터가 명령을 완벽히 따라갈 때다.
  이 구간은 정렬 상태(지연 0)에서 출발해 약 1도 뒤처진 상태로 끝난다(구간 평균 오차
  0.9~1.0도). 51.4 − 1.2 ≈ 50.2. 오차 표와 부호 판정 값이 서로 맞아떨어진다
- **속도가 오르면 지연이 커진다** (57 deg/s 에서 1.1~1.2도 → 171 deg/s 에서 1.5도).
  오픈루프는 전압을 고정해 넣으므로, 빨리 돌수록 역기전력이 인가 전압을 깎아 전류가
  준다 → 같은 마찰 토크를 내려면 부하각이 더 벌어져야 한다
- **역방향에서 오차 부호가 뒤집힌다.** 로터는 항상 명령보다 *뒤*에 있다 — 방향이
  바뀌면 뒤도 바뀐다
- 부하각을 전기각으로 바꾸면 약 1.5 × 7 ≈ **10도(전기)**. 최대 90도까지 여유가 크다.
  무부하라 필요한 토크가 마찰·코깅뿐이어서다

### 원인 판정 — 정직하게

이번에 **자석 고정 방식(테이프 → 접착 플러그)** 과 **신호 세기(AGC 128 → 21)** 를
함께 바꿨다. 그래서 08-29 드리프트가 둘 중 무엇 때문이었는지는 엄밀히 가를 수 없다.
확실한 것은 두 가지다:

- 지금 구성에서는 **회전 중 AGC 가 한 번도 안 흔들렸다** → 이 간격에서 PWM 간섭은 없다
- 오차가 **1도대로 줄었고 두 번 다 재현된다** → 지금 각도는 믿을 수 있다

가르고 싶다면 스페이서를 빼서(AGC 128) 같은 실험을 돌려보면 된다. 그때 드리프트가
다시 나오면 약신호 간섭, 안 나오면 테이프 미끄러짐이었다.

### 다음

엔코더가 믿을 만해졌으니 이제 **각도를 "읽는" 단계에서 "쓰는" 단계**로 간다.

1. **전기각 오프셋 캘리브레이션** — 엔코더 0도와 자석(d축) 0도의 차이를 한 번 잰다.
   정렬 벡터를 걸고 그 순간의 엔코더 값을 기록하는 절차
2. **엔코더 기반 정류** — 매 루프 각도를 읽어 벡터를 `θe + 90도` 에 세운다.
   부하각을 항상 최적(90도)에 고정 = 전류 센서 없는 "전압 모드 FOC". 오픈루프와 달리
   부하가 걸려도 탈조하지 않아야 한다
3. 이후 전류 센싱(OPAMP + ADC) → 전류 루프 → 진짜 FOC

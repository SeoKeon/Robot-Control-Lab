# 2026-10-10 위치 루프 — 한 바퀴 넘게 돌았다 와도 같은 자리, 밀면 버티고 놓으면 돌아온다

## 뭘 하려고 했나

[속도 루프](2026-10-10-speed-loop.md)까지 닫혔으니 캐스케이드의 맨 바깥, **각도를 명령**하는
위치 루프를 얹는다. 로봇 관절이 실제로 받는 명령은 "이 각도로 가라"다.

```
목표각 → [사다리꼴 궤적] → 위치 P → 속도 지령 → 속도 PI → iq 지령 → 전류 루프
             └── 속도 피드포워드 ──┘            └── 가속 피드포워드 J·a/Kt ──┘
```

## 뭘 했나

### 설계

| 항목 | 값 | 이유 |
|---|---|---|
| 위치 게인 Kp | 2π·4 = 25 /s | 위치 루프 대역폭 4 Hz = 속도 루프(15 Hz)의 약 1/4. 오차 1도 → 속도 지령 약 4 rpm |
| 속도 지령 한계 | ±200 rpm | 크게 밀렸다 놓였을 때 돌아오는 속도 제한 |
| 궤적 | 최고 120 rpm, 가속도 300 rad/s² | 90도 이동 167 ms, 450도 이동 667 ms |
| 가속 피드포워드 | J·a/Kt ≈ 17.5 mA | 궤적이 원하는 가속에 필요한 토크를 미리 |
| 위치 측정 | 엔코더 언랩 누적 (멀티턴) | 0 = 실행 시작 위치 |
| 안전 | 오차 90도 초과면 정지 | 부호 오류·폭주 대비 |

위치 루프에는 적분기를 따로 두지 않았다. 안쪽 속도 PI 의 적분기가 있어서, 일정한 부하에서도
정지 상태가 되려면 `Kp·오차 = 0` 이어야 한다 → 정지 위치 오차는 0 으로 간다.

### 1. 손 안 대는 이동 (`p`)

| 단계 | 목표 | 1초 뒤 평균 위치 | 이동 중 최대 오차 |
|---|---|---|---|
| 0 유지 | 0 | −0.02 (떨림 ±0.5) | — |
| +90 | 90 | **90.05** | 3.1 |
| +450 (한 바퀴 더) | 450 | **450.02** | 5.9 |
| 복귀 | 0 | **0.24** | 8.0 |
| +30 계단 (궤적 없음) | 30 | 30.07 | (처음 30) |
| 0 | 0 | 0.18 | 7.4 |

- **멀티턴**: 1.25 바퀴를 갔다 와도 처음 자리에서 0.2도 안쪽 (엔코더 한 칸 = 0.088도)
- 120 rpm 등속 중 오차 ±2~3도 — 속도 루프에서 본 한 바퀴 부하가 그대로 위치 오차가 된다
- 루프 1920~1940 Hz 일정

### 2. 위치 유지 + 손으로 밀기 (`h`, 20 s)

약 12번, 양방향으로 최대 42도까지 밀었다(90도 안전장치는 한 번도 안 걸림).

| 관찰 | 값 |
|---|---|
| 밀린 채로 버티는 동안 | iq 가 0.1~0.2 s 에 걸쳐 한계 150 mA(약 13 mN·m)까지 올라감 — 10도만 밀어도 결국 한계 |
| 놓은 뒤 반대로 넘어가는 양 | **8~19도 — 밀린 거리(10~42도)와 거의 무관** |
| ±2도 안으로 돌아오는 시간 | 0.3~0.4 s |
| ±0.2도 안까지 | 약 1 s (마지막은 천천히 기어감) |
| 끝난 뒤 정지 | 오차 0.0~0.5도, iq 약 12 mA |

## 막힌 것과 해결 과정

### 궤적 없는 계단이 생각보다 얌전했다

"궤적 없이 계단을 주면 튄다"를 보여주려고 넣은 30도 계단은 0.4도만 넘어갔다. 위치 P 는 **남은
거리에 비례하는 속도**를 지령하므로 계단을 줘도 시정수 1/Kp = 40 ms 의 지수함수로 다가간다.
궤적이 필요한 진짜 이유는 다른 데서 보였다:

- 출발 순간 **토크 충격** — 계단은 iq 지령 72 mA 에서 시작(최대치가 처음에), 궤적 90도 이동은 최대 54 mA
- 먼 거리면 속도 지령이 한계(200 rpm)에 막혀 도착 시각을 제어할 수 없다
- 로봇팔에서 여러 관절이 **같이 출발해 같이 도착**하려면 시간이 정해진 궤적이 필요하다

### 정지 직전에 끈적인다 (stick-slip)

- +30 계단: 19도에서 약 50 ms 멈춤. 그동안 iq 지령이 28 → 46 mA 로 올라간 뒤에야 다시 움직임
- 복귀 이동 끝: 7.9도에서 걸림 → 적분기가 쌓인 뒤 풀리며 −4.2도까지 넘어감 → 거기서 또 200 ms 멈춤
  → 약 1.5 s 에 0 근처 안착

**손으로 확인 (PWM 끈 뒤)**: 한 바퀴 돌려보니 약 20도 구간이 아주 살짝 뻑뻑했다. 한 번 돌릴 땐
몰랐고 여러 번 돌리고서야 느꼈을 정도 — 그런데 제어기는 이걸 iq 18 mA 어치(28 → 46 mA, 약
1.5 mN·m)로 또렷하게 "느꼈다". 손보다 전류 센서가 마찰에 훨씬 민감하다.

**움직이기 시작하는 데 필요한 힘(정지 마찰)이 굴러갈 때 마찰보다 큰** 구간이 있다. 멈추면
적분기가 정지 마찰을 넘을 때까지 쌓이고, 넘는 순간 풀린 힘이 남아서 넘어간다. 속도 루프의 한 바퀴
부하와 같은 원인으로 보인다 — 위치 제어에서는 이게 **정지 정밀도와 안착 시간**을 정한다.

### 놓았을 때 넘어가는 양이 밀린 거리와 무관하다

처음엔 "많이 밀수록 많이 튈 것"이라 예상했는데 8~19도로 거의 일정했다. 밀린 채로 있는 동안
속도 PI 의 출력이 iq 한계(150 mA)에 붙는다. 그중 비례 항 몫을 뺀 나머지가 **적분기에 저장된 토크**고,
anti-windup 이 적분기를 한계 근처에서 멈춰두므로 그 크기는 밀린 거리와 상관없이 비슷하다. 놓는
순간 이 저장된 토크가 로터를 밀고, 목표를 지날 때까지 다 못 갚아서 넘어간다.

해볼 만한 개선 (기록만):
- 위치 루프에 적분을 두고 속도 PI 는 P 만 — 저장되는 위치가 바뀐다
- 속도 지령 한계(200 rpm)를 낮춰 돌아오는 속도를 줄인다
- 오차가 클 때는 적분을 서서히 비우는 방식 (조건부 적분의 변형)

## 배운 것 / 다음 할 것

- 캐스케이드 세 층(전류 → 속도 → 위치)이 같은 방식으로 쌓였다: 플랜트 측정 → 대역폭 → 게인 → 제한
- 위치 루프 성능의 한계는 제어기보다 **기구(마찰)** 쪽에서 먼저 나왔다
- 궤적의 가치는 "튀지 않게"보다 **토크 충격과 도착 시각 제어**에 있다
- 한 바퀴 부하의 정체: 손으로도 약 20도 뻑뻑한 구간 확인 (원인 — 지그 접촉? 베어링? 자석 홀더? — 은 미확인)
- 남은 숙제: 모터로 **마찰 지도** 그리기(아주 느린 일정 속도로 한 바퀴 돌며 각도별 iq 기록 →
  뻑뻑한 구간의 위치·폭·크기) · 그 지도로 마찰 보상 · 놓았을 때 넘어가는 양 줄이기
- p1 은 여기까지. 다음은 로봇팔 — 2축 기구학, 중력 보상, 여러 보드 동기

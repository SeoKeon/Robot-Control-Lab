# 2026-10-10 전류 루프 — FOC 완성: 잡아도 명령한 전류만 흐른다

## 뭘 하려고 했나

오늘 오전의 [전압 모드 정류](2026-10-10-first-closed-loop-commutation.md)는 전압 크기 m 을
명령하고 전류는 결과로 따라 나왔다. 그래서 **잡고 있으면 전류가 V/R(159 mA)까지 커지고
막을 장치가 없었다.** 전류 센싱과 dq 변환, 각도 지연 보정이 다 갖춰졌으니 이제
**전류(= 토크)를 직접 명령**한다. id = 0, iq = 원하는 토크.

## 뭘 했나

### 설계 — 측정값으로 정한 제어기

| 근거 | 값 | 출처 |
|---|---|---|
| 루프 주기 | 약 0.54 ms (1.86 kHz) | I2C 각도 읽기가 정함 |
| 플랜트 | 사실상 저항 — L/R 이 루프 주기보다 짧아 다음 루프에서 이미 새 전류 | 짐벌모터 |
| 상저항 R | 10.5 Ω | 상간 21 Ω 실측 / 2 |
| 역기전력 상수 ψ | 8.14 mV·s/rad(전기) | τ 스윕: 266 rpm 에서 E = Vq − R·iq = 1.59 V |

```
Vq = R·iq_지령 + ψ·ω    (피드포워드 — 필요한 전압을 미리 계산, 대부분을 맡는다)
   + 적분기               (나머지만 천천히: 게인 0.2·R → 루프마다 오차 20% 감소)
Vd = 적분기               (id 를 0 으로)
```

피드포워드가 대부분을 맡으므로 적분 게인을 작게 잡을 수 있고, 그만큼 샘플당
σ ≈ 30 mA 의 전류 노이즈에 둔감하다. 전압 크기 m ≤ 0.40 으로 제한하고 포화 중에는
적분을 멈춘다(anti-windup). 안전: 100 ms 평균 |iq| > 0.3 A, 1200 rpm 초과, `q` 면 정지.

### 1. 손 안 대는 확인 (`i`)

| 단계 | iq 지령 | 측정 iq | id | rpm | m |
|---|---|---|---|---|---|
| 1 | 0 | −0.6 ~ +0.9 | ≈ 0 | 멈춰 있음 | 3% |
| 2 | +40 mA | 첫 0.1초 +32.8, 이후 18~28 | 3~8 | 0 → 360 | 40% (한계) |
| 3 | −40 mA | 첫 0.1초 **−39.3**, 이후 −16~−31 | −2~6 | +360 → −360 | 40% (한계) |
| 4 | 0 | ≈ 0 | ≈ 0 | 멈춤 | 3% |

- 지령 0 이면 전류도 0 → 토크 0 → 그 자리에 가만히 있다. 전압 모드의 "전압 0" 은
  권선 단락 브레이크였는데, 전류 0 은 진짜로 "놓아준" 상태다
- 전압 여유가 있으면 지령을 정확히 따른다 (3단계 첫 0.1초, 포화 0%: −40 → −39.3)
- 무부하에 토크를 계속 주면 역기전력이 전압 한계(m=40%)에 닿는 360 rpm 까지 가속하고,
  그다음은 전압이 모자라 iq 가 지령 아래로 떨어진다(포화 100%). 토크 제어의 정상 동작

## 막힌 것과 해결 과정

### 전원 표시로는 차이가 안 보인다 — 상전류 ≠ 버스 전류

모터 전류는 159 → 100 mA 로 1.6배 차이인데 전원 표시는 0.16 → 0.14 A. 전원공급장치가
보여주는 것은 **12 V 버스 전류**이고, 그 대부분(약 0.12 A)은 보드 자체 소비다. 모터 몫은
전력으로 환산해야 한다:

```
P = 1.5 × Vq × iq          (진폭 불변형 dq 기준)
전압 모드: 1.5 × 1.8 V × 0.159 A ≈ 0.43 W → 버스 약 36 mA
전류 루프: 1.5 × 1.16 V × 0.100 A ≈ 0.17 W → 버스 약 15 mA
```

차이 약 20 mA 가 표시값 차이와 맞는다. 손 느낌도 마찬가지 — 토크로 8.6 대 13.6 mN·m
(Kt = 1.5 × 7 × ψ ≈ 0.086 N·m/A)라 손가락으로는 구분이 어렵다. **감각이 아니라 데이터로
갈린 결과다.**

### 포화 중에는 id 도 못 맞춘다 — 개선점

무부하로 전압 한계에 붙어 있을 때 id 가 −9 ~ −14 mA 로 0 에서 벗어났다(때로는 +6).
포화되면 d/q 적분기를 **둘 다** 멈추게 했기 때문에, 그동안 id 조절도 같이 멈추고 멈춘
시점의 적분값에 따라 id 가 달라진다. 표준 개선법은 **남은 전압을 d축에 먼저 주고 q축에
나머지를 주는 것**(d축 우선 제한). 정지·저속에서는 포화가 없어 id 가 정확히 0 이었다.

### 열린 질문 — 토크 0 인데 너무 빨리 멈췄다

`i` 의 4단계(iq = 0)에서 −360 rpm 이 약 20 ms 만에 멈췄다. 같은 날 측정으로 보면 360 rpm
의 마찰은 약 23 mA 상당이고, 로터 관성(2단계 가속에서 역산 약 5×10⁻⁶ kg·m²)으로는
마찰만으로 약 0.1 s 가 걸려야 한다. 그 100 ms 동안 측정 iq 평균은 0 이었다 — 100 ms 평균
으로는 짧은 순간이 안 보인다. 단계 전환 직후를 더 촘촘히 기록해서 다시 볼 것.

## 배운 것 / 다음 할 것

- **전류 루프의 가치는 "막혔을 때"에 있다.** 무부하에서는 전압 모드와 별 차이가 없어
  보이지만, 잡는 순간 전압 모드는 V/R 까지 가고 전류 루프는 지령에 머문다
- **피드포워드가 일을 하고 적분기는 다듬는다.** 플랜트를 측정해 두면(R, ψ) 작은 게인으로도
  잘 따라가고 노이즈에 강하다. 오늘 앞 실험들에서 잰 숫자가 그대로 설계값이 됐다
- **포화는 설계의 일부다.** 무부하 토크 제어는 반드시 전압 한계에 닿는다. 그때 무엇을
  포기할지(여기서는 q 를 줄이고 d 를 지키는 것)를 정해야 한다

### 다음

1. d축 우선 전압 제한 (포화 중 id = 0 유지)
2. **속도 루프** — 속도 PI → iq 지령. [PID 캐스케이드 노트](../notes/2026-07-22-pid-cascade-structure.md)의
   "안쪽부터" 순서대로: 전류(완료) → 속도 → 위치. p1 의 완료 기준이 "전류 루프가 닫힌
   상태로 속도 지령을 따라가는 것"이다
3. 열린 질문: 토크 0 감속을 촘촘히 기록

# 2026-08-29 자기식 절대각 엔코더 — AS5600 의 원리와 진단

<!-- 오늘 실측(±2카운트 안정, AGC=128, 드리프트 비재현)을 예로 쓴다 -->

## 왜 찾아봤나

FOC 는 로터 각도 하나에 전부를 건다. 그 각도를 주는 센서가 어떤 원리로 읽고,
어떤 조건에서 무너지고, 무너지기 전에 어떤 신호를 주는지 모르면 — 나중에
모터가 이상하게 돌 때 제어 코드와 센서 중 어디를 의심할지 판단할 수 없다.
오늘 자석 부재 → 신호 한계 → 드리프트를 연달아 겪으며 그 판단 기준이 생겼다.

## 핵심

### 1. 읽는 원리 — 자기장의 "방향"을 각도로

칩 다이 중앙에 홀 소자 4개가 십자로 배열돼 있고, 바로 위에서 도는
**지름방향(diametral) 자석**의 자기장 방향을 읽는다.

```
      자석 (축과 함께 회전)
    ┌────┬────┐
    │ N  │  S │     자기장이 "옆"을 향한다. 자석이 돌면 방향이 같이 돈다
    └────┴────┘
         ↕ 0.5~3mm
    ┌──────────┐
    │  H    H  │    소자 4개가 각자 위치에서 세기를 재고,
    │     ·    │    그 비율의 atan 으로 방향을 역산 → 12비트 (0~4095)
    │  H    H  │
    └──────────┘
```

여기서 모든 요구사항이 따라나온다:

| 요구 | 이유 |
|---|---|
| **지름방향 자화** 필수 | 일반(축방향) 자석은 돌아도 4소자 비율이 안 변함 — 방향 정보가 없다 |
| **칩 정중앙** 위에 자석 | 소자 배열이 중앙 대칭. 편심되면 비율이 왜곡 → 비선형 오차 |
| **간격 0.5~3mm** | 자기장은 거리에 급감. 멀면 신호↓, 너무 가까우면 포화 |
| 비접촉 | 마모 없음. 짐벌·FOC 용으로 쓰이는 이유 |

### 2. 절대각 vs 증분 — 부팅하면 바로 안다

AS5600 은 **절대각(absolute)** 센서다. 전원을 켜는 순간 "지금 몇 도"를 안다.
ABZ 펄스를 세는 증분형(incremental)은 기준점 찾기(호밍)가 필요하다.

단, "절대"는 **자석 기준**이다. 전기각 0도(자석 정렬 방향)와는 무관하므로
FOC 전에 **오프셋 캘리브레이션**이 한 번 필요하다 — d축으로 강제 정렬해서
그 순간의 엔코더 값을 읽는 절차 (08-20 노트의 "initFOC 덜컥"의 정체).

### 3. 진단 레지스터 — 센서가 자기 상태를 말해준다

오늘 디버깅의 핵심 도구. **값을 읽기 전에 이걸 먼저 읽는 습관.**

| 레지스터 | 뜻 | 오늘 실전에서 |
|---|---|---|
| STATUS(0x0B) bit5 **MD** | 자석 감지됨 | 목표. 아직 0 |
| bit4 **ML** | 자석 너무 약함/멀다 (AGC 최대 도달) | 자석 부재·간격 과다를 이걸로 잡음 |
| bit3 **MH** | 너무 강함/가깝다 | 한 번도 안 뜸 = 가까울 위험은 없음 |
| **AGC(0x1A)** | 자동 게인 잔량. 3.3V 모드 0~128 | **거리 게이지.** 128 고정 = 증폭 한계 = 사실상 무신호. 이상적 ~64 |

AGC 를 정량 게이지로 쓰는 법: 지그에서 서포트 높이/와셔를 바꿔가며
**AGC 60~90** 에 들어오게 조정한다. MD=1 은 그 부산물로 따라온다.

### 4. 언랩(unwrap) — 12비트 값을 연속 각도로

raw 는 4095 다음 0 으로 되돌아간다(랩어라운드). 연속 회전을 추적하려면:

```c
d = raw - prev;
if (d >  2048) d -= 4096;   /* 뒤로 랩 */
if (d < -2048) d += 4096;   /* 앞으로 랩 */
acc += d;  prev = raw;
```

"두 샘플 사이 이동이 반 바퀴(2048)를 넘지 않는다"는 가정이 깔려 있다.
→ **샘플링 주기가 회전 속도의 상한을 정한다.** 500Hz 폴링이면 기계
250 rps(15000 rpm)까지 이론상 안전 — 우리 속도에선 여유가 크다.
단 **노이즈 스파이크가 2048 을 넘으면 언랩이 한 바퀴를 잘못 세므로**,
신호가 약할 때(AGC 최대) 언랩 누적값은 랜덤워크 위험이 있다.

### 5. 신호가 약하면 무엇이 끼어드나 — SNR 이야기

엔코더 자석 신호가 약하면(AGC=128) 다른 자기장이 상대적으로 커 보인다:

- **로터 링 자석 누설**: 14극이 축과 함께 도는 복잡한 패턴
- **스테이터 전류 자기장**: PWM 전류가 만드는 회전 자기장 — **통전 중에만** 존재

오늘 드리프트(1차 -44도 / 2차 -21.6도, 비재현)의 후보가 이 간섭과
기계 미끄러짐(테이프 고정) 둘이다. 가르는 방법이 아래 6번.

### 6. 진단 방법론 — 오늘의 진짜 수확

**① 재현성 검사**: 같은 입력을 두 번. 오차가 같으면 계통(스케일·설정·극쌍수),
매번 다르면 랜덤(기계 미끄러짐·노이즈). 오늘 90.9 vs 64.0 → 랜덤 확정.

**② 변인 제거 실험**: 후보가 둘이면 하나를 끌 수 있는 실험을 설계한다.
전원 OFF + 손으로 정확히 2바퀴 → PWM 간섭이 사라진 조건에서 720도가
나오는지. 맞으면 간섭, 틀리면 미끄러짐. (펌웨어 준비됨, 고정 후 실행)

**③ 물리 한계로 상한 검증**: 순수 부하각은 최대 90도(전기)/7 = **12.9도(기계)**.
관측 오차 40~50도 » 12.9도 → "부하각만으로는 설명 불가, 다른 원인이 지배적"
이라는 결론이 계산 한 줄에서 나온다. **기대값을 먼저 계산해두면 이상치가
스스로 정체를 밝힌다.**

### 7. I2C 로 읽는다는 것의 대가 (미리 알아둘 것)

100kHz I2C 로 각도 1회 읽기 ≈ 0.5ms. 지금(500Hz 폴링)은 여유지만, FOC 전류
루프는 보통 10~20kHz 로 돈다 — **I2C 로는 전류 루프 주기마다 각도를 못 읽는다.**
해법들(속도 400kHz, 각도 보간/외삽, 또는 SPI 엔코더로 업그레이드 — J8 의
PB6/PB7 이 TIM4_CH1/CH2 라 ABI 방식도 같은 커넥터로 가능)은 그때 가서 고른다.
지금 단계(각도 관측, 저속 정류)에는 I2C 로 충분하다.

## 실습 연결

- 다음 실행 순서: 엔코더 기구 고정 → 무전원 손돌리기(±720도 검증) → 원인 조치
  → 통합 실험 재실행 (성공 기준: 51.4±2도 / 최종 ±13도 / 2회 재현)
- 통과하면 엔코더 기반 정류: 매 루프 각도를 읽어 벡터를 θe+90도에 세운다.
  전류 센서 없이도 "각도 피드백 FOC" 의 절반이 완성된다

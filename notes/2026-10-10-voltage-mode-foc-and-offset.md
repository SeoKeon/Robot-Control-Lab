# 2026-10-10 전압 모드 FOC 와 전기각 오프셋 — 엔코더로 모터를 "당기는" 법

<!-- 오늘 실측(오프셋 −72.5도, 정/역 255/−251 rpm, 전류 0.13→0.16A)을 예로 쓴다 -->

## 왜 찾아봤나

엔코더 각도가 정확해졌는데(±1도), 그 각도를 어떻게 써야 모터가 "알아서" 도는지,
캘리브레이션은 왜 필요하고 왜 여러 점에서 재는지, 그리고 오늘 본 숫자들
(속도가 전압에 비례, 누르면 전류가 느는 것)이 왜 그렇게 나오는지 정리한다.

## 핵심

### 1. 정류(commutation) = "항상 90도 앞을 당긴다"

[오픈루프 노트](2026-08-27-openloop-vector-and-why-foc.md)에서 정리한 대로 토크는

```
τ ∝ m × sin(δ)      δ = 벡터 각 − 로터 각 (전기각)
```

δ = 90도에서 최대다. 오픈루프는 로터 각을 몰라서 δ 가 상황에 따라 0~90도 아무
값이고, 90도를 넘으면 탈조한다. 엔코더가 있으면:

```c
θe = 부호 × 극쌍수 × θm(엔코더) + 오프셋;     // 로터의 전기각
벡터를 θe + 90도 에 세운다;                    // δ = 90도 고정
```

**δ 가 항상 90도** — 같은 전압으로 낼 수 있는 최대 토크, 그리고 탈조가 원리적으로
없다. 멈춰 세웠다 놓아도 "지금 로터 위치에서 90도 앞"을 다시 당길 뿐이다.
방향은 +90 / −90 으로 정한다.

### 2. 오프셋 — 엔코더 0도는 자석 0도가 아니다

엔코더는 **자석 기준** 절대각을 준다. 그런데 정류에 필요한 건 **전기각** —
U상 방향(벡터 0도)에 로터 d축(자석 N극)이 정렬된 위치가 0도다. 엔코더 칩을
어떤 각도로 붙였는지, 자석을 어떻게 끼웠는지에 따라 이 둘의 차이는 아무 값이나
될 수 있다. 오늘 값은 −72.5도였다. 이 값을 모르면 "90도 앞"이 실제로는 엉뚱한
각도가 된다.

### 3. 캘리브레이션을 여러 점에서 하는 이유

가장 단순한 방법은 벡터를 0도에 세워 로터를 끌어당긴 뒤, 그때 엔코더 값을 읽는
것이다(SimpleFOC 의 `initFOC` 가 대략 이렇다 — "덜컥"). 문제는 **마찰과 코깅**이다.
로터가 δ=0 까지 완전히 가지 못하고 조금 앞에서 멈추면 그 차이가 오프셋 오차가 된다.

그래서 오늘은:

- **24점**(30도씩 앞으로 12, 뒤로 12)에서 오프셋을 각각 구해 평균
  → 위치마다 다른 코깅 영향이 평균된다
- **앞으로 갈 때와 뒤로 갈 때**를 같이 쓴다 → 마찰 때문에 앞으로 갈 땐 뒤처지고
  뒤로 갈 땐 반대로 뒤처지는데, 둘이 서로 상쇄된다 (오늘 앞뒤 차 −0.1도 — 마찰이
  작다는 뜻이기도 하다)
- **원형 평균**을 쓴다. 각도는 360도에서 0도로 넘어가서 그냥 더하면 안 된다
  (359도와 1도의 평균은 0도인데 산술평균은 180도). 각을 단위벡터 (cos, sin)로
  바꿔 더한 뒤 `atan2` 로 되돌린다

흩어짐 최대 7.9도(전기) = 기계로 약 1.1도. 코깅과 자석·칩 정렬의 비선형이 남긴
흔적이고, 평균에는 영향이 작다. **2회 반복 차이 0.0도**가 결과의 신뢰도다.

### 4. 오프셋이 맞는지 따로 확인하는 법 — 정방향/역방향 대칭

캘리브레이션 숫자를 믿는 것과 별개로, **결과로 검증**할 수 있다. 오프셋이 ε 만큼
틀렸다면 정방향은 실제 앞섬이 90+ε, 역방향은 90−ε 가 되어 토크가 달라지고
속도가 달라진다. 오늘 255 / −251 rpm (1.6% 차) → ε 가 매우 작다.

### 5. 전압 모드에서 일어나는 일 — 역기전력이 주인공

모터 한 상의 전압 방정식(정상상태 근사):

```
V(인가) = R × I + E(역기전력),    E = Ke × ω (속도에 비례)
→  I = (V − Ke·ω) / R
```

오늘 본 현상이 전부 이 한 줄에서 나온다.

| 관찰 | 설명 |
|---|---|
| 정지 벡터(캘리브레이션) 0.2A | ω = 0 → E = 0 → 전압이 전부 저항에 → 전류 큼 |
| 회전 중 0.13A | ω 가 커져 E 가 V 를 거의 상쇄 → 마찰 이길 만큼만 흐름 |
| 무부하 속도 ∝ m (845 ≈ 850) | 무부하면 I ≈ 0 → V ≈ Ke·ω → ω ∝ V |
| 누르면 0.13 → 0.16A, "밀어냄" | ω 감소 → E 감소 → I 증가 → 토크 증가. 저절로 |
| 잡고 있으면 전류 최대 | ω = 0 → I = V/R. **제한할 장치가 없다** |

마지막 줄이 전압 모드의 한계이고, 다음 단계(전류 루프)가 필요한 이유다.

### 6. 전류 루프로 가면 무엇이 바뀌나 (예고)

지금은 "전압 m 을 준다 → 전류(=토크)는 속도에 따라 결과적으로 정해진다".
전류 루프는 반대로 "전류(토크) iq 를 정한다 → 필요한 전압은 제어기가 알아서 낸다".
그러면:

- 막혀도 iq 지령 이상은 안 흐른다 (모터·드라이버 보호)
- 속도와 무관하게 같은 토크 — 로봇 관절에 필요한 것은 이것
- d축 전류 id = 0 으로 두면 자석 방향으로 낭비되는 전류가 없다

필요한 것: 3상 전류 측정(내장 OPAMP + ADC, center-aligned 꼭대기 샘플링 →
[PWM 노트](2026-08-27-tim1-complementary-pwm-deadtime.md) §6), Clarke/Park 변환,
PI 제어기 두 개.

### 7. 루프 지연 — 빨라질수록 90도가 무너진다

각도는 I2C 로 읽어서 루프가 약 2 kHz, 각도가 최대 0.5 ms 늦다. 그 사이 로터가
움직인 만큼 실제 앞섬이 줄어든다:

```
지연 각(전기) = 극쌍수 × 기계속도 × 지연시간
255 rpm: 7 × (255/60 × 360도/s) × 0.0005 s ≈ 5.4도   → 실제 앞섬 약 85도
```

지금은 작지만 속도에 비례해 커진다. 해법은 I2C 400 kHz, 속도로 각도 외삽
(θ + ω·Δt), 또는 SPI/ABI 엔코더.

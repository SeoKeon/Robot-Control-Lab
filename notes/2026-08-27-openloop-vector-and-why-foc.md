# 2026-08-27 오픈루프 벡터 구동 — 왜 돌아가고, 왜 이걸로는 부족한가

<!-- 오늘 실측(m=0.30 추종 부족, m=0.45 완전 추종, off 시 4.29도 안착)을 예로 쓴다 -->

## 왜 찾아봤나

`bsp_pwm_set_vector()` 가 duty 세 개를 계산해서 넣으면 로터가 그 방향으로
"딸깍" 붙는다. 오늘 눈으로 봤다. 그런데 **왜** 붙는지, 왜 m=0.30 에선 뒤처지고
0.45 에선 따라오는지, 왜 이 방식이 최종 목적지(FOC)가 아닌지를 정리해둬야
다음 단계에서 뭘 측정해야 하는지가 보인다.

## 핵심

### 1. duty 세 개 = 전압 벡터 하나

```c
duty_U = 0.5 + 0.5·m·cos(θe)
duty_V = 0.5 + 0.5·m·cos(θe − 120°)
duty_W = 0.5 + 0.5·m·cos(θe + 120°)
```

- **0.5 오프셋**: 하프브리지는 음전압을 못 만든다 (0V~12V 뿐). 세 상을 전부
  중간(6V)에 띄워놓고 그 위아래로 흔들면, 상끼리의 **차이**는 음수가 된다.
  모터는 선간 전압만 보므로 이걸로 충분하다
- **120° 간격 cos 세 개**: 한 점에서 보면 그냥 사인파지만, 세 코일이 공간적으로
  120° 벌어져 있어서 **합성 자기장은 크기가 일정한 채 방향만 θe 를 가리킨다**
  (크기 1.5·I — 08-20 노트에서 정리한 회전자기장 그것)
- **m (변조 크기)**: 벡터의 길이. 상전압 진폭 = 0.5·m·Vbus.
  m=0.45, 12V → 상전압 피크 2.7V → 상저항 10.5Ω 에서 상전류 피크 약 0.26A.
  전원공급장치 표시(DC 평균)는 그보다 낮게 나온다 — 오늘 0.2A 미만 관측과 일치

### 2. 로터가 붙는 이유 — 토크는 sin(어긋난 각)

로터 자석은 스테이터 자기장과 **정렬하려고** 한다. 토크는:

```
τ ∝ m × sin(δ)        δ = 스테이터 벡터 각 − 로터 자석 각 (전기각)
```

- δ = 0 (정렬됨): 토크 0. 여기가 평형점 — 벡터를 세워두면 로터가 여기 앉는다
- δ = 90°: **토크 최대**. 이 각을 유지하는 게 이상적
- δ > 90°: 오히려 토크가 줄어든다 → 더 벌어지면 미끄러진다 (탈조)

"딸깍" 붙는 건 δ=0 평형점으로 끌려가는 것. 스프링에 매달린 것과 같아서,
평형점 주변에서 흔들리다 감쇠하며 앉는다.

### 3. 오늘 관측 3개를 이 틀로 해석

**① m=0.30 에서 94도 기대에 70도만 이동**
스텝마다 로터는 δ=0 까지 가려 하지만, 코깅+마찰이 버틴다. 남은 미소각에서
sin(δ)·토크가 마찰보다 작아지면 거기서 멈춘다 — 스텝마다 조금씩 덜 가고,
누적되면 24도 부족. **m 을 올리면 같은 δ 에서 토크가 커져** 잔차가 줄어든다.
m=0.45 에서 완전 추종된 이유.

**② PWM off 시 4.29도 안쪽 역방향 미동**
전류가 끊기면 sin(δ) 토크가 사라지고 코깅 토크만 남는다. 로터는 가장 가까운
코깅 디텐트(간격 360/LCM(12,14) = 4.29도)로 안착. 고장이 아니라
"유지 토크가 실제로 걸려 있었다"는 증거.

**③ 5단계 속도 전부 추종, 탈조 없음**
속도를 올리면 로터가 벡터를 따라가느라 δ 가 벌어진다. δ 가 90도를 넘는 순간
탈조하는데, 오늘 범위(기계 457deg/s)에선 도달 못 함. 무부하 + 저관성이라
한계가 훨씬 위에 있다.

### 4. 오픈루프의 비용 — 왜 FOC 로 가는가

오늘 방식은 **로터가 어디 있는지 모른 채** 벡터를 밀어붙이는 것이다. 그 대가:

| 문제 | 원인 |
|---|---|
| 전류 낭비 | δ 를 모르니 항상 최악을 가정해 m 을 크게. δ≈0 근처에서는 토크 거의 없이 열만 발생 |
| 토크 예측 불가 | 같은 m 이라도 δ 에 따라 토크가 0~최대 사이 아무 값 |
| 탈조 위험 | 부하가 갑자기 커져 δ>90° 가 되는 순간 제어 상실. 복구 수단 없음 |
| 속도 한계 | δ 여유를 남겨야 하니 이론 최대 토크의 일부만 사용 |

**FOC 의 아이디어는 한 줄이다: δ 를 측정해서 항상 90도로 유지한다.**
그러려면 두 가지를 실시간으로 알아야 한다:

```
로터 각도  → AS5600 엔코더 (I2C)          ← 다음 단계 후보 1
상전류     → 3션트 + 내장 OPAMP + ADC      ← 다음 단계 후보 2
```

각도를 알면 벡터를 "로터+90도"에 세울 수 있고(δ 고정), 전류를 알면 토크를
직접 제어할 수 있다(전류 루프). 둘 다 있으면 08-20 노트의 d/q 축 이야기가
코드가 된다 — d축(자석 방향) 전류는 0으로, q축(90도) 전류로 토크를.

### 5. 다음에 공부할 키워드 (순서대로)

1. **Clarke / Park 변환** — 3상 전류(ia,ib,ic)를 회전 좌표(id,iq) 두 개로.
   "왜 3개가 2개로 줄어도 정보가 안 사라지나" (힌트: ia+ib+ic=0)
2. **ADC injected conversion + TIM1 TRGO** — center-aligned 꼭대기 샘플링을
   하드웨어로 엮는 방법 (RM0440)
3. **SVPWM vs 사인 변조** — 지금 코드는 사인. SVPWM(또는 3차 고조파 주입)은
   같은 Vbus 에서 선간 전압을 15% 더 뽑는다. 왜 그런지
4. **AS5600 I2C 프로토콜** — 12비트 각도 읽기, 그리고 I2C 속도가 제어 주기에
   충분한가 (스포일러: 아슬아슬하다. 그래서 FOC 보드들이 SPI 엔코더를 선호)
5. **전기각 오프셋 캘리브레이션** — 엔코더 0도와 자석 0도는 다르다.
   d축으로 강제 정렬해서 오프셋을 재는 표준 절차 (08-20 노트에 적어둔
   "initFOC 에서 덜컥 움직이는 것"의 정체)

## 실습 연결

- 엔코더가 붙으면 오늘 코드로 바로 실험 하나가 된다: 오픈루프로 돌리면서
  "명령각 vs 측정각"을 시리얼로 나란히 찍기 → δ 가 속도·부하에 따라 벌어지는
  것을 눈으로 확인 → FOC 의 필요성이 데이터로 남는다
- 전류 센싱이 붙으면: 정지 벡터 상태에서 ia+ib+ic ≈ 0 확인이 첫 검증
